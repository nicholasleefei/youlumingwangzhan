## 1. Problem Statement（问题陈述）

**我们在解决什么具体的用户痛点或业务机会？**

运营团队手动下载汽车之家车型物料，单次新车发布需要 **100 小时**，存在速度慢、操作繁琐、图片质量不稳定（分辨率不够、有水印、图片不全）的问题，导致内容更新滞后，影响用户体验。

**谁遇到了这个问题、频率如何、不解决的代价是什么？**

- **用户：** 运营团队（3-10 人）
- **频率：** 新车发布时 + 历史车型补全（几十款）
- **代价：** 运营时间消耗在重复性劳动上，内容更新滞后，用户体验受损

**Evidence（证据）：**

- User research（用户研究）：内部访谈 n=1，确认"手动下载太慢、太麻烦、质量不稳定"
- Behavioral data（行为数据）：当前单次处理 100 小时，目标 10 小时（10x 提升）
- Support signal（客服信号）：内容更新滞后导致的用户反馈
- Competitive signal（竞争信号）：暂无

### 核心用户故事及验收标准

**Story 1: 作为运营专员，我想要输入品牌+车型官方名称，然后一键下载所有物料，以便快速完成车型内容更新。**

**Acceptance Criteria（验收标准）：**

- [ ] Given（场景）用户打开工具首页，when（操作）输入品牌+车型官方名称，then（预期）系统能正确匹配到汽车之家对应车型页面
- [ ] Given（场景）车型匹配成功，when（操作）点击"开始下载"按钮，then（预期）系统开始爬取所有物料类型
- [ ] Given（场景）下载进行中，when（操作）查看进度页面，then（预期）显示实时进度（已下载/总数，当前正在下载的类型）
- [ ] Given（场景）下载完成，when（操作）查看结果，then（预期）提供 ZIP 压缩包下载，文件结构符合要求

**Story 2: 作为运营专员，我想要 360VR 图按颜色分类下载并放到不同子文件夹，且包含色号信息，以便后续按颜色快速查找使用。**

**Acceptance Criteria（验收标准）：**

- [ ] Given（场景）车型有多种颜色的 360VR，when（操作）下载完成，then（预期）360VR 文件夹下按颜色创建子文件夹
- [ ] Given（场景）颜色子文件夹已创建，when（操作）查看文件夹名称，then（预期）文件夹名称包含色号（如："珠光白\_#FFFFFF"）
- [ ] Given（场景）颜色子文件夹已创建，when（操作）打开文件夹，then（预期）该颜色的所有 360VR 图片都在此文件夹内

**Story 3: 作为运营专员，我想要下载后的物料按约定类型分类存放，以便快速找到所需类型的图片。**

**Acceptance Criteria（验收标准）：**

- [ ] Given（场景）下载完成，when（操作）解压 ZIP 包，then（预期）根目录下有以下文件夹：

- [ ] Given（场景）各类型文件夹已创建，when（操作）打开文件夹，then（预期）对应类型的所有图片都在正确的文件夹内
- [ ] Given（场景）图片已下载，when（操作）查看图片文件，then（预期）图片为高清原图，无水印

## 5. Solution Overview（方案概述）

**产品方案：**

一个网页版内部工具，包含以下核心功能：

1. **首页：** 支持两种输入方式
   - 方式 A：输入品牌+车型官方名称，点击"搜索车系" → 显示搜索结果，用户选择正确车系
   - 方式 B：直接输入车系ID（从汽车之家 URL 复制）
   - 选择后，点击"开始下载"
2. **进度页：** 实时显示下载进度（当前类型、已下载/总数）
3. **结果页：** 下载完成后提供 ZIP 包下载，显示成功/失败统计

**关键 UX 流程：**

```
方式 A（推荐）：
用户打开工具 → 输入品牌+车型 → 点击"搜索车系" → 选择正确车系 → 点击"开始下载" → 查看实时进度 → 下载完成 → 下载 ZIP 包

方式 B（备选）：
用户打开工具 → 直接输入车系ID（如 5769）→ 点击"开始下载" → 查看实时进度 → 下载完成 → 下载 ZIP 包
```

**Key Design Decisions（关键设计决策）：**

| Decision（决策）                 | Rationale（理由）              | Tradeoff（取舍）        |
| ---------------------------- | -------------------------- | ------------------- |
| V1 仅支持汽车之家                   | 范围可控，先验证核心价值               | 未来如需扩展到其他网站需要重构部分逻辑 |
| 网页版而非命令行                     | 运营使用门槛低，用户体验好              | 开发量比命令行稍大           |
| ZIP 包输出而非直接存服务器              | 简单、灵活，用户可自行管理存放位置          | 需要额外下载步骤            |
| 人工触发而非定时检测                   | 范围可控，避免误爬                  | 新车发布时需要有人记得去触发      |
| 支持两种输入方式（品牌+车型搜索 + 直接输入车系ID） | 没有现成映射表，方式 A 体验好，方式 B 简单可靠 | 开发量稍大，但能同时满足体验和可靠性  |

## 6. Technical Considerations（技术考量）

### 6.1 汽车之家网站结构研究发现（已确认）

基于对汽车之家公开页面的分析，确认以下技术细节：

| 项                   | 发现                                                                             |
| ------------------- | ------------------------------------------------------------------------------ |
| **车系 URL 结构**       | 每个车系有唯一数字 ID，URL 格式：`https://www.autohome.com.cn/{车系ID}/`（如特斯拉 Model Y 是 5769） |
| **图库入口**            | 图库页面链接格式：`/cars/imglist-x-x-{车系ID}-x-x-x-x-x-x-1.html`                         |
| **360° VR 入口**      | 全景看车链接格式：`https://pano.autohome.com.cn/car/ext/{VR全景ID}`（如 Model Y 是 76157）    |
| **360VR 颜色**        | 全景页面上有"个性配色"选项，支持多颜色切换，色号信息需从页面 DOM/JS 数据中提取                                   |
| **品牌+车型 → 车系ID 匹配** | 需要研究汽车之家搜索接口，实现用户输入"特斯拉 Model Y" → 返回车系列表供选择                                   |

***

### 6.2 技术方案建议

**推荐技术栈：**

| 层    | 技术选型                 | 理由                                              |
| ---- | -------------------- | ----------------------------------------------- |
| 前端   | React + Tailwind CSS | 组件化开发快，UI 灵活                                    |
| 后端   | Python + FastAPI     | 爬虫生态丰富（Playwright/BeautifulSoup/Scrapy），API 开发快 |
| 爬虫引擎 | Playwright           | 支持动态页面渲染，处理 JavaScript 生成的内容                    |
| 部署   | Docker + 内网服务器       | 隔离环境，易于管理                                       |

**爬虫核心流程：**

```
1. 用户输入"特斯拉 Model Y" 或直接输入车系ID（如 5769）
2a. 如果是品牌+车型：调用搜索接口 → 返回前 3 个结果 → 用户选择正确车系
2b. 如果是车系ID：直接使用
3. 访问车系首页，提取各物料入口链接
4. 分别爬取：外观图、内饰图、细节图、外观360VR、内饰360VR、品牌官方图
5. 360VR：遍历所有颜色，提取该颜色下的所有 VR 图片序列
6. 按约定文件夹结构组织文件
7. 打包 ZIP，提供下载
```
